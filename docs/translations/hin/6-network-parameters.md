## Genesis ब्लॉक पैरामीटर

### Base Target गणना

**सूत्र**: `genesis_base_target = 2^42 / block_time_seconds`

**तर्क**:
- प्रत्येक nonce 256 KiB का प्रतिनिधित्व करता है (64 बाइट्स × 4096 scoops)
- 1 TiB = 2^22 nonces (प्रारंभिक नेटवर्क क्षमता धारणा)
- n nonces के लिए अपेक्षित न्यूनतम गुणवत्ता ≈ 2^64 / n
- 1 TiB के लिए: E(quality) = 2^64 / 2^22 = 2^42
- इसलिए: base_target = 2^42 / block_time

**गणना किए गए मान**:
- Mainnet/Testnet/Signet (120s): `36650387592`
- Regtest (1s): कम-क्षमता कैलिब्रेशन मोड का उपयोग करता है

### Genesis संदेश

Each network has its own genesis message. See `src/kernel/chainparams.cpp` for details.

## सहमति पैरामीटर

### समय पैरामीटर

**MAX_FUTURE_BLOCK_TIME**: `15` सेकंड
- PoCX-विशिष्ट (Bitcoin 2 घंटे उपयोग करता है)
- तर्क: PoC समय को निकट-वास्तविक-समय सत्यापन की आवश्यकता होती है
- भविष्य में 15s से अधिक के ब्लॉक अस्वीकृत होते हैं

**समय ऑफ़सेट चेतावनी**: `10` सेकंड
- जब नोड घड़ी नेटवर्क समय से >10s ड्रिफ्ट करती है तो ऑपरेटरों को चेतावनी दी जाती है
- कोई प्रवर्तन नहीं, केवल सूचनात्मक

**ब्लॉक समय लक्ष्य**:
- Mainnet/Testnet/Signet: `120` सेकंड
- Regtest: `1` सेकंड

**TIMESTAMP_WINDOW**: `15` सेकंड (MAX_FUTURE_BLOCK_TIME के बराबर)

**कार्यान्वयन**: `src/chain.h`, `src/validation.cpp`

### कठिनाई समायोजन पैरामीटर

**रोलिंग विंडो आकार**: `24` ब्लॉक (सभी नेटवर्क)
- हाल के ब्लॉक समय का घातांकीय मूविंग एवरेज
- प्रत्येक-ब्लॉक समायोजन
- क्षमता परिवर्तनों के प्रति प्रतिक्रियाशील

**कार्यान्वयन**: `src/consensus/params.h`, ब्लॉक निर्माण में कठिनाई लॉजिक

### असाइनमेंट सिस्टम पैरामीटर

**nForgingAssignmentDelay** (सक्रियण विलंब):
- Mainnet: `30` ब्लॉक (~1 घंटा)
- Testnet: `30` ब्लॉक (~1 घंटा)
- Regtest: `4` ब्लॉक (~4 सेकंड)

**nForgingRevocationDelay** (निरस्तीकरण विलंब):
- Mainnet: `720` ब्लॉक (~24 घंटे)
- Testnet: `720` ब्लॉक (~24 घंटे)
- Regtest: `8` ब्लॉक (~8 सेकंड)

**तर्क**:
- सक्रियण विलंब ब्लॉक दौड़ के दौरान तेज़ पुनर्असाइनमेंट रोकता है
- निरस्तीकरण विलंब स्थिरता प्रदान करता है और दुरुपयोग रोकता है

**कार्यान्वयन**: `src/consensus/params.h`

## Coinbase और ब्लॉक पुरस्कार

### ब्लॉक सब्सिडी अनुसूची

**प्रारंभिक सब्सिडी**: `10 BTC` (सभी नेटवर्क)

**Halving अनुसूची**:
- प्रत्येक `1050000` ब्लॉक (mainnet/testnet)
- प्रत्येक `500` ब्लॉक (regtest)
- अधिकतम 64 halvings तक जारी

**Halving प्रगति**:
```
Halving 0: 10.00000000 BTC  (ब्लॉक 0 - 1049999)
Halving 1:  5.00000000 BTC  (ब्लॉक 1050000 - 2099999)
Halving 2:  2.50000000 BTC  (ब्लॉक 2100000 - 3149999)
Halving 3:  1.25000000 BTC  (ब्लॉक 3150000 - 4199999)
...
```

**कुल आपूर्ति**: ~21 मिलियन BTC (Bitcoin के समान)

### Coinbase आउटपुट नियम

**भुगतान गंतव्य**:
- **कोई असाइनमेंट नहीं**: Coinbase plot पते (proof.account_id) को भुगतान करता है
- **असाइनमेंट के साथ**: Coinbase फोर्जिंग पते (प्रभावी हस्ताक्षरकर्ता) को भुगतान करता है

**आउटपुट प्रारूप**: केवल P2WPKH
- Coinbase bech32 SegWit v0 पते को भुगतान करना चाहिए
- प्रभावी हस्ताक्षरकर्ता की सार्वजनिक कुंजी से उत्पन्न

**असाइनमेंट रिज़ॉल्यूशन**:
```cpp
effective_signer = GetEffectiveSigner(plot_address, height, view);
coinbase_script = P2WPKH(effective_signer);
```

**कार्यान्वयन**: `src/pocx/mining/block_builder.cpp:BuildBlock()`

## डायनामिक स्केलिंग

### स्केलिंग सीमाएं

**उद्देश्य**: क्षमता मुद्रास्फीति रोकने के लिए नेटवर्क परिपक्व होने पर plot जनरेशन कठिनाई बढ़ाएं

**संरचना**:
```cpp
struct PoCXCompressionBounds {
    uint32_t nPoCXMinCompression;     // न्यूनतम स्वीकृत स्तर
    uint32_t nPoCXTargetCompression;  // अनुशंसित स्तर
};
```

**संबंध**: `target = min + 1` (हमेशा न्यूनतम से एक स्तर ऊपर)

### स्केलिंग वृद्धि अनुसूची

स्केलिंग स्तर halving अंतरालों के आधार पर **घातांकीय अनुसूची** पर बढ़ते हैं:

| समय अवधि | ब्लॉक ऊंचाई | Halvings | Min | Target |
|-------------|--------------|----------|-----|--------|
| वर्ष 0-4 | 0 से 1049999 | 0 | X1 | X2 |
| वर्ष 4-12 | 1050000 से 3149999 | 1-2 | X2 | X3 |
| वर्ष 12-28 | 3150000 से 7349999 | 3-6 | X3 | X4 |
| वर्ष 28-60 | 7350000 से 15749999 | 7-14 | X4 | X5 |
| वर्ष 60-124 | 15750000 से 32549999 | 15-30 | X5 | X6 |
| वर्ष 124+ | 32550000+ | 31+ | X6 | X7 |

**मुख्य ऊंचाइयां** (वर्ष → halvings → ब्लॉक):
- वर्ष 4: Halving 1 ब्लॉक 1050000 पर
- वर्ष 12: Halving 3 ब्लॉक 3150000 पर
- वर्ष 28: Halving 7 ब्लॉक 7350000 पर
- वर्ष 60: Halving 15 ब्लॉक 15750000 पर
- वर्ष 124: Halving 31 ब्लॉक 32550000 पर

### स्केलिंग स्तर कठिनाई

**PoW स्केलिंग**:
- स्केलिंग स्तर X0: POC2 बेसलाइन (सैद्धांतिक)
- स्केलिंग स्तर X1: XOR-transpose बेसलाइन
- स्केलिंग स्तर Xn: 2^(n-1) × X1 कार्य एम्बेडेड
- प्रत्येक स्तर plot जनरेशन कार्य को दोगुना करता है

**आर्थिक संरेखण**:
- ब्लॉक पुरस्कार आधे होते हैं → plot जनरेशन कठिनाई बढ़ती है
- सुरक्षा मार्जिन बनाए रखता है: plot निर्माण लागत > लुकअप लागत
- हार्डवेयर सुधारों से क्षमता मुद्रास्फीति रोकता है

### Plot सत्यापन

**सत्यापन नियम**:
- सबमिट किए गए proofs में स्केलिंग स्तर ≥ न्यूनतम होना चाहिए
- स्केलिंग > target वाले Proofs स्वीकार लेकिन अक्षम
- न्यूनतम से नीचे के Proofs: अस्वीकृत (अपर्याप्त PoW)

**सीमाएं पुनर्प्राप्ति**:
```cpp
auto bounds = GetPoCXCompressionBounds(height, halving_interval);
```

**कार्यान्वयन**: `src/pocx/consensus/params.h:GetPoCXCompressionBounds()`, `src/pocx/consensus/params.cpp`

## डेटा निर्देशिका संरचना

### डिफ़ॉल्ट निर्देशिका

**स्थान**: `.bitcoin/` (Bitcoin Core के समान)
- Linux: `~/.bitcoin/`
- macOS: `~/Library/Application Support/Bitcoin/`
- Windows: `%APPDATA%\Bitcoin\`

### निर्देशिका सामग्री

```
.bitcoin/
├── blocks/              # ब्लॉक डेटा
│   ├── blk*.dat        # ब्लॉक फ़ाइलें
│   ├── rev*.dat        # Undo डेटा
│   └── index/          # ब्लॉक इंडेक्स (LevelDB)
├── chainstate/         # UTXO सेट + फोर्जिंग असाइनमेंट (LevelDB)
├── wallets/            # वॉलेट फ़ाइलें
│   └── wallet.dat      # डिफ़ॉल्ट वॉलेट
├── bitcoin.conf        # कॉन्फ़िगरेशन फ़ाइल
├── debug.log           # डीबग लॉग
├── peers.dat           # Peer पते
├── mempool.dat         # Mempool persistence
└── banlist.dat         # प्रतिबंधित peers
```

### Bitcoin से मुख्य अंतर

**Chainstate डेटाबेस**:
- मानक: UTXO सेट
- **PoCX जोड़**: फोर्जिंग असाइनमेंट स्थिति
- परमाणु अपडेट: UTXO + असाइनमेंट एक साथ अपडेट
- असाइनमेंट के लिए Reorg-सुरक्षित undo डेटा

**ब्लॉक फ़ाइलें**:
- मानक Bitcoin ब्लॉक प्रारूप
- **PoCX जोड़**: PoCX प्रमाण फ़ील्ड के साथ विस्तारित (account_id, seed, nonce, signature, pubkey)

### कॉन्फ़िगरेशन फ़ाइल उदाहरण

**bitcoin.conf**:
```ini
# नेटवर्क चयन
#testnet=1
#regtest=1

# PoCX माइनिंग सर्वर (बाहरी माइनर्स के लिए आवश्यक)

# RPC सेटिंग्स
server=1
rpcuser=yourusername
rpcpassword=yourpassword
rpcallowip=127.0.0.1
rpcport=8332

# कनेक्शन सेटिंग्स
listen=1
port=8338
```
