# अध्याय 1: परिचय और अवलोकन

## Bitcoin-PoCX क्या है?

Bitcoin-PoCX एक Bitcoin Core एकीकरण है जो **Proof of Capacity neXt generation (PoCX)** सहमति समर्थन जोड़ता है। यह Bitcoin Core की मौजूदा आर्किटेक्चर को बनाए रखते हुए Proof of Work के पूर्ण प्रतिस्थापन के रूप में एक ऊर्जा-कुशल Proof of Capacity माइनिंग विकल्प सक्षम करता है।

**मुख्य अंतर**: यह Bitcoin PoW के साथ पश्चगामी संगतता के बिना एक **नई चेन** है। PoCX ब्लॉक डिज़ाइन द्वारा PoW नोड्स के साथ असंगत हैं।

## Proof of Capacity क्या है?

Proof of Capacity (PoC) एक सहमति तंत्र है जहां माइनिंग पावर कम्प्यूटेशनल पावर के बजाय **डिस्क स्पेस** के अनुपात में होती है। माइनर क्रिप्टोग्राफिक हैश वाली बड़ी plot फ़ाइलें पूर्व-उत्पन्न करते हैं, फिर वैध ब्लॉक समाधान खोजने के लिए इन plots का उपयोग करते हैं।

**ऊर्जा दक्षता**: Plot फ़ाइलें एक बार उत्पन्न होती हैं और अनिश्चित काल तक पुन: उपयोग की जाती हैं। माइनिंग न्यूनतम CPU पावर का उपभोग करती है—मुख्य रूप से डिस्क I/O।

**PoCX संवर्द्धन**:
- XOR-transpose compression attack को ठीक किया (POC2 में 50% समय-मेमोरी ट्रेडऑफ़)
- आधुनिक हार्डवेयर के लिए 16-nonce-संरेखित लेआउट
- Plot जनरेशन में स्केलेबल proof-of-work (Xn स्केलिंग स्तर)
- सीधे Bitcoin Core में नेटिव C++ एकीकरण
- बेहतर ब्लॉक समय वितरण के लिए Time Bending एल्गोरिथम

## आर्किटेक्चर अवलोकन

### रिपॉजिटरी संरचना

```
bitcoin-pocx/
├── bitcoin/             # Bitcoin Core v30.2 + PoCX एकीकरण
│   └── src/pocx/        # PoCX कार्यान्वयन
├── pocx/                # PoCX core framework (सबमॉड्यूल, केवल-पढ़ने योग्य)
└── docs/                # यह दस्तावेज़ीकरण
```

### एकीकरण दर्शन

**न्यूनतम एकीकरण सतह**: परिवर्तन `/src/pocx/` निर्देशिका में अलग हैं जिनके Bitcoin Core सत्यापन, माइनिंग, और RPC परतों में स्वच्छ हुक हैं।

**फ़ीचर फ़्लैगिंग**: सभी संशोधन `#ifdef ENABLE_POCX` प्रीप्रोसेसर गार्ड के तहत। अक्षम होने पर Bitcoin Core सामान्य रूप से बिल्ड होता है।

**अपस्ट्रीम संगतता**: पृथक एकीकरण बिंदुओं के माध्यम से Bitcoin Core अपडेट के साथ नियमित सिंक बनाए रखा गया।

**नेटिव C++ कार्यान्वयन**: सहमति सत्यापन के लिए स्केलर क्रिप्टोग्राफिक एल्गोरिथम (Shabal256, scoop गणना, compression) सीधे Bitcoin Core में एकीकृत।

## मुख्य विशेषताएं

### 1. पूर्ण सहमति प्रतिस्थापन

- **ब्लॉक संरचना**: PoCX-विशिष्ट फ़ील्ड PoW nonce और difficulty bits को प्रतिस्थापित करते हैं
  - Generation signature (नियतात्मक माइनिंग एन्ट्रॉपी)
  - Base target (कठिनाई का विलोम)
  - PoCX proof (account ID, seed, nonce, compression, quality)
  - Block signature (plot स्वामित्व सिद्ध करता है)

- **सत्यापन**: हेडर जांच से ब्लॉक कनेक्शन तक 5-चरण सत्यापन पाइपलाइन

- **कठिनाई समायोजन**: हाल के base targets के मूविंग एवरेज का उपयोग करते हुए प्रत्येक-ब्लॉक समायोजन

### 2. Time Bending एल्गोरिथम

**समस्या**: पारंपरिक PoC ब्लॉक समय घातांकीय वितरण का पालन करते हैं, जब कोई माइनर अच्छा समाधान नहीं पाता तो लंबे ब्लॉक होते हैं।

**समाधान**: घन मूल का उपयोग करते हुए घातांकीय से ची-वर्ग में वितरण परिवर्तन: `Y = scale × (X^(1/3))` where `X = raw_quality / base_target`।

**प्रभाव**: Extremely fast blocks are delayed and extremely slow blocks are shortened, reducing variance while preserving average block time at 120 seconds.

**विवरण**: [अध्याय 3: सहमति और माइनिंग](3-consensus-and-mining.md)

### 3. फोर्जिंग असाइनमेंट सिस्टम

**क्षमता**: Plot मालिक plot स्वामित्व बनाए रखते हुए फोर्जिंग अधिकार अन्य पतों को प्रत्यायोजित कर सकते हैं।

**उपयोग के मामले**:
- पूल माइनिंग (plots पूल पते को असाइन करते हैं)
- कोल्ड स्टोरेज (माइनिंग की plot स्वामित्व से अलग)
- बहु-पक्षीय माइनिंग (साझा बुनियादी ढांचा)

**आर्किटेक्चर**: OP_RETURN-केवल डिज़ाइन—कोई विशेष UTXOs नहीं, असाइनमेंट chainstate डेटाबेस में अलग से ट्रैक किए गए।

**विवरण**: [अध्याय 4: फोर्जिंग असाइनमेंट](4-forging-assignments.md)

### 4. डिफेंसिव फोर्जिंग

**समस्या**: तेज़ घड़ियां 15-सेकंड भविष्य सहनशीलता के भीतर समय लाभ प्रदान कर सकती हैं।

**समाधान**: समान ऊंचाई पर प्रतिस्पर्धी ब्लॉक प्राप्त करते समय, स्वचालित रूप से स्थानीय गुणवत्ता जांचें। यदि बेहतर है, तो तुरंत फोर्ज करें।

**प्रभाव**: घड़ी हेरफेर के लिए प्रोत्साहन समाप्त—तेज़ घड़ियां केवल तभी मदद करती हैं जब आपके पास पहले से सबसे अच्छा समाधान हो।

**विवरण**: [अध्याय 5: समय सुरक्षा](5-timing-security.md)

### 5. डायनामिक Compression स्केलिंग

**आर्थिक संरेखण**: स्केलिंग स्तर आवश्यकताएं घातांकीय अनुसूची पर बढ़ती हैं (वर्ष 4, 12, 28, 60, 124 = halvings 1, 3, 7, 15, 31)।

**प्रभाव**: जैसे-जैसे ब्लॉक पुरस्कार घटते हैं, plot जनरेशन कठिनाई बढ़ती है। Plot निर्माण और लुकअप लागत के बीच सुरक्षा मार्जिन बनाए रखता है।

**रोकता है**: समय के साथ तेज़ हार्डवेयर से क्षमता मुद्रास्फीति।

**विवरण**: [अध्याय 6: नेटवर्क पैरामीटर](6-network-parameters.md)

## डिज़ाइन दर्शन

### कोड सुरक्षा

- पूरे में रक्षात्मक प्रोग्रामिंग प्रथाएं
- सत्यापन पथों में व्यापक त्रुटि हैंडलिंग
- कोई नेस्टेड लॉक नहीं (डेडलॉक रोकथाम)
- परमाणु डेटाबेस संचालन (UTXO + असाइनमेंट एक साथ)

### मॉड्यूलर आर्किटेक्चर

- Bitcoin Core इंफ्रास्ट्रक्चर और PoCX सहमति के बीच स्वच्छ पृथक्करण
- PoCX core framework क्रिप्टोग्राफिक primitives प्रदान करता है
- Bitcoin Core सत्यापन फ्रेमवर्क, डेटाबेस, नेटवर्किंग प्रदान करता है

### प्रदर्शन अनुकूलन

- फास्ट-फेल सत्यापन क्रम (सस्ती जांच पहले)
- प्रति सबमिशन एकल संदर्भ फ़ेच (कोई दोहराया cs_main अधिग्रहण नहीं)
- स्थिरता के लिए परमाणु डेटाबेस संचालन

### Reorg सुरक्षा

- असाइनमेंट स्थिति परिवर्तनों के लिए पूर्ण undo डेटा
- चेन टिप परिवर्तनों पर फोर्जिंग स्थिति रीसेट
- सभी सत्यापन बिंदुओं पर staleness पहचान

## PoCX Proof of Work से कैसे भिन्न है

| पहलू | Bitcoin (PoW) | Bitcoin-PoCX |
|--------|---------------|--------------|
| **माइनिंग संसाधन** | कम्प्यूटेशनल पावर (हैश रेट) | डिस्क स्पेस (क्षमता) |
| **ऊर्जा खपत** | उच्च (निरंतर हैशिंग) | निम्न (केवल डिस्क I/O) |
| **माइनिंग प्रक्रिया** | hash < target वाला nonce खोजें | deadline < elapsed time वाला nonce खोजें |
| **कठिनाई** | `bits` फ़ील्ड, हर 2016 ब्लॉक में समायोजित | `base_target` फ़ील्ड, हर ब्लॉक में समायोजित |
| **ब्लॉक समय** | ~10 मिनट (घातांकीय वितरण) | 120 सेकंड (time-bended, कम विचलन) |
| **सब्सिडी** | 50 BTC → 25 → 12.5 → ... | 10 BTC → 5 → 2.5 → ... |
| **हार्डवेयर** | ASICs (विशेषीकृत) | HDDs (कमोडिटी हार्डवेयर) |
| **माइनिंग पहचान** | अनाम | Plot मालिक या प्रतिनिधि |

## सिस्टम आवश्यकताएं

### नोड संचालन

**Bitcoin Core के समान**:
- **CPU**: आधुनिक x86_64 प्रोसेसर
- **मेमोरी**: 4-8 GB RAM
- **स्टोरेज**: नई चेन, वर्तमान में खाली (2-मिनट ब्लॉक और असाइनमेंट डेटाबेस के कारण Bitcoin से ~5× तेज़ बढ़ सकती है)
- **नेटवर्क**: स्थिर इंटरनेट कनेक्शन
- **क्लॉक**: इष्टतम संचालन के लिए NTP सिंक्रनाइज़ेशन अनुशंसित

**नोट**: नोड संचालन के लिए Plot फ़ाइलों की आवश्यकता नहीं है।

### माइनिंग आवश्यकताएं

**माइनिंग के लिए अतिरिक्त आवश्यकताएं**:
- **Plot फ़ाइलें**: `pocx_plotter` (संदर्भ कार्यान्वयन) का उपयोग करके पूर्व-उत्पन्न
- **माइनर सॉफ़्टवेयर**: `pocx_miner` (संदर्भ कार्यान्वयन) RPC के माध्यम से कनेक्ट होता है
- **वॉलेट**: माइनिंग पते के लिए निजी कुंजियों वाला `bitcoind` या `bitcoin-qt`। पूल माइनिंग के लिए स्थानीय वॉलेट की आवश्यकता नहीं है।

## शुरू करना

### 1. Bitcoin-PoCX बनाएं

```bash
# सबमॉड्यूल के साथ क्लोन करें
git clone --recursive https://github.com/PoC-Consortium/bitcoin-pocx.git
cd bitcoin-pocx/bitcoin

# Build
cmake -B build
cmake --build build
```

**Details**: See `bitcoin/doc/build-*.md` for platform-specific build instructions

### 2. नोड चलाएं

**केवल नोड**:
```bash
./build/bin/bitcoind
# या
./build/bin/bitcoin-qt
```

**माइनिंग के लिए** (बाहरी माइनर्स के लिए RPC पहुंच सक्षम करता है):
```bash
./build/bin/bitcoind
# या
./build/bin/bitcoin-qt -server
```

**विवरण**: [अध्याय 6: नेटवर्क पैरामीटर](6-network-parameters.md)

### 3. Plot फ़ाइलें जनरेट करें

PoCX-प्रारूप plot फ़ाइलें जनरेट करने के लिए `pocx_plotter` (संदर्भ कार्यान्वयन) का उपयोग करें।

**विवरण**: [अध्याय 2: Plot प्रारूप](2-plot-format.md)

### 4. माइनिंग सेटअप करें

अपने नोड के RPC इंटरफ़ेस से कनेक्ट करने के लिए `pocx_miner` (संदर्भ कार्यान्वयन) का उपयोग करें।

**विवरण**: [अध्याय 7: RPC संदर्भ](7-rpc-reference.md) और [अध्याय 8: वॉलेट गाइड](8-wallet-guide.md)

## एट्रिब्यूशन

### Plot प्रारूप

POC2 प्रारूप (Burstcoin) पर आधारित संवर्द्धन के साथ:
- सुरक्षा दोष ठीक किया (XOR-transpose compression attack)
- स्केलेबल proof-of-work
- SIMD-अनुकूलित लेआउट

### स्रोत परियोजनाएं

## तकनीकी विनिर्देश सारांश

- **ब्लॉक समय**: 120 सेकंड (mainnet), 1 सेकंड (regtest)
- **ब्लॉक सब्सिडी**: 10 BTC प्रारंभिक, हर 1050000 ब्लॉक (~4 वर्ष) में halving
- **कुल आपूर्ति**: ~21 मिलियन BTC (Bitcoin के समान)
- **भविष्य सहनशीलता**: 15 सेकंड (15s आगे तक के ब्लॉक स्वीकार किए जाते हैं)
- **क्लॉक चेतावनी**: 10 सेकंड (समय ड्रिफ्ट की ऑपरेटरों को चेतावनी देता है)
- **असाइनमेंट विलंब**: 30 ब्लॉक (~1 घंटा)
- **निरस्तीकरण विलंब**: 720 ब्लॉक (~24 घंटे)
- **पता प्रारूप**: PoCX माइनिंग संचालन और फोर्जिंग असाइनमेंट के लिए केवल P2WPKH (bech32, pocx1q...)

## सुरक्षा विचार

### समय सुरक्षा

- 15-सेकंड भविष्य सहनशीलता नेटवर्क विखंडन रोकती है
- 10-सेकंड चेतावनी सीमा ऑपरेटरों को क्लॉक ड्रिफ्ट के बारे में सचेत करती है
- डिफेंसिव फोर्जिंग घड़ी हेरफेर के लिए प्रोत्साहन समाप्त करती है
- Time Bending समय विचलन के प्रभाव को कम करती है

**विवरण**: [अध्याय 5: समय सुरक्षा](5-timing-security.md)

### असाइनमेंट सुरक्षा

- OP_RETURN-केवल डिज़ाइन (कोई UTXO हेरफेर नहीं)
- लेनदेन हस्ताक्षर plot स्वामित्व सिद्ध करता है
- सक्रियण विलंब तेज़ स्थिति हेरफेर रोकता है
- सभी स्थिति परिवर्तनों के लिए Reorg-सुरक्षित undo डेटा

**विवरण**: [अध्याय 4: फोर्जिंग असाइनमेंट](4-forging-assignments.md)

### सहमति सुरक्षा

- ब्लॉक हैश से हस्ताक्षर बाहर रखा गया (malleability रोकता है)
- बाउंडेड हस्ताक्षर आकार (DoS रोकता है)
- Compression बाउंड्स सत्यापन (कमज़ोर proofs रोकता है)
- प्रत्येक-ब्लॉक कठिनाई समायोजन (क्षमता परिवर्तनों के प्रति प्रतिक्रियाशील)
