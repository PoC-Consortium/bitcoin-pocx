## Преглед

### Карактеристике Bitcoin-PoCX новчаника

Bitcoin-PoCX Qt новчаник (`bitcoin-qt`) пружа:
- Стандардну функционалност Bitcoin Core новчаника (слање, примање, управљање трансакцијама)
- **Менаџер додељивања ковања**: GUI за креирање/опозивање додељивања плотова
- **Режим сервера за рударење**: `` флаг омогућава функције везане за рударење
- **Историја трансакција**: Приказ трансакција додељивања и опозива

### Покретање новчаника

**Само чвор** (без рударења):
```bash
./build/bin/bitcoin-qt
```

**Са рударењем** (омогућава дијалог додељивања):
```bash
./build/bin/bitcoin-qt -server
```

**Алтернатива командне линије**:
```bash
./build/bin/bitcoind
```

### Захтеви за рударење

**За операције рударења**:
- Потребан `` флаг
- Новчаник са P2WPKH адресама и приватним кључевима
- Спољни плотер (`pocx_plotter`) за генерисање плотова
- Спољни рудар (`pocx_miner`) за рударење

**За рударење у пулу**:
- Креирајте додељивање ковања на адресу пула
- Новчаник није потребан на серверу пула (пул управља кључевима)

## Дијалог додељивања ковања

### Приступање дијалогу

**Мени**: `Новчаник → Додељивања ковања`
**Трака алата**: Икона рударења (видљива само са `` флагом)
**Величина прозора**: 600×450 пиксела

### Режими дијалога

#### Режим 1: Креирање додељивања

**Сврха**: Делегирање права ковања пулу или другој адреси док се задржава власништво над плотом.

**Случајеви употребе**:
- Рударење у пулу (додели адреси пула)
- Хладно складиштење (кључ за рударење одвојен од власништва над плотом)
- Дељена инфраструктура (делегирај на hot wallet)

**Захтеви**:
- Адреса плота (P2WPKH bech32, мора имати приватни кључ)
- Адреса ковања (P2WPKH bech32, различита од адресе плота)
- Новчаник откључан (ако је шифрован)
- Адреса плота има потврђене UTXO-е

**Кораци**:
1. Изаберите режим „Креирај додељивање"
2. Изаберите адресу плота из падајућег менија или унесите ручно
3. Унесите адресу ковања (пул или делегат)
4. Кликните „Пошаљи додељивање" (дугме омогућено када су уноси важећи)
5. Трансакција се одмах емитује
6. Додељивање активно након `nForgingAssignmentDelay` блокова:
   - Mainnet/Testnet: 30 блокова (~1 сат)
   - Regtest: 4 блока (~4 секунде)

**Накнада за трансакцију**: Подразумевано 10× `minRelayFee` (подесиво)

**Структура трансакције**:
- Улаз: UTXO од адресе плота (доказује власништво)
- OP_RETURN излаз: `POCX` маркер + plot_address + forging_address (46 бајтова)
- Излаз за кусур: Враћен новчанику

#### Режим 2: Опозив додељивања

**Сврха**: Откажи додељивање ковања и врати права власнику плота.

**Захтеви**:
- Адреса плота (мора имати приватни кључ)
- Новчаник откључан (ако је шифрован)
- Адреса плота има потврђене UTXO-е

**Кораци**:
1. Изаберите режим „Опозови додељивање"
2. Изаберите адресу плота
3. Кликните „Пошаљи опозив"
4. Трансакција се одмах емитује
5. Опозив ефективан након `nForgingRevocationDelay` блокова:
   - Mainnet/Testnet: 720 блокова (~24 сата)
   - Regtest: 8 блокова (~8 секунди)

**Ефекат**:
- Адреса ковања може још увек ковати током периода кашњења
- Власник плота враћа права након завршетка опозива
- Може креирати ново додељивање после

**Структура трансакције**:
- Улаз: UTXO од адресе плота (доказује власништво)
- OP_RETURN излаз: `XCOP` маркер + plot_address (26 бајтова)
- Излаз за кусур: Враћен новчанику

#### Режим 3: Провера статуса додељивања

**Сврха**: Упит тренутног стања додељивања за било коју адресу плота.

**Захтеви**: Нема (само за читање, новчаник није потребан)

**Кораци**:
1. Изаберите режим „Провери статус додељивања"
2. Унесите адресу плота
3. Кликните „Провери статус"
4. Поље статуса приказује тренутно стање са детаљима

**Индикатори стања** (означени бојом):

**Сиво - UNASSIGNED**
```
UNASSIGNED - Нема додељивања
```

**Наранџасто - ASSIGNING**
```
ASSIGNING - Додељивање чека активацију
Адреса ковања: pocx1qforger...
Креирано на висини: 12000
Активира се на висини: 12030 (још 5 блокова)
```

**Зелено - ASSIGNED**
```
ASSIGNED - Активно додељивање
Адреса ковања: pocx1qforger...
Креирано на висини: 12000
Активирано на висини: 12030
```

**Црвено-наранџасто - REVOKING**
```
REVOKING - Опозив у току
Адреса ковања: pocx1qforger... (још увек активна)
Додељивање креирано на висини: 12000
Опозвано на висини: 12300
Опозив ефективан на висини: 13020 (још 50 блокова)
```

**Црвено - REVOKED**
```
REVOKED - Додељивање опозвано
Раније додељено: pocx1qforger...
Додељивање креирано на висини: 12000
Опозвано на висини: 12300
Опозив ефективан на висини: 13020
```

## Историја трансакција

### Приказ трансакција додељивања

**Тип**: „Додељивање"
**Икона**: Икона рударења (иста као за рудареним блоковима)

**Колона адресе**: Адреса плота (адреса чија се права ковања додељују)
**Колона износа**: Накнада трансакције (негативно, одлазна трансакција)
**Колона статуса**: Број потврда (0-6+)

**Детаљи** (када се кликне):
- ID трансакције
- Адреса плота
- Адреса ковања (парсирана из OP_RETURN)
- Креирано на висини
- Висина активације
- Накнада трансакције
- Временска ознака

### Приказ трансакција опозива

**Тип**: „Опозив"
**Икона**: Икона рударења

**Колона адресе**: Адреса плота
**Колона износа**: Накнада трансакције (негативно)
**Колона статуса**: Број потврда

**Детаљи** (када се кликне):
- ID трансакције
- Адреса плота
- Опозвано на висини
- Висина ефективног опозива
- Накнада трансакције
- Временска ознака

### Филтрирање трансакција

**Доступни филтери**:
- „Све" (подразумевано, укључује додељивања/опозиве)
- Опсег датума
- Опсег износа
- Претрага по адреси
- Претрага по ID трансакције
- Претрага по ознаци (ако је адреса означена)

**Напомена**: Трансакције додељивања/опозива тренутно се појављују под филтером „Све". Наменски филтер типа још није имплементиран.

### Сортирање трансакција

**Редослед сортирања** (по типу):
- Генерисано (тип 0)
- Примљено (тип 1-3)
- Додељивање (тип 4)
- Опозив (тип 5)
- Послато (тип 6+)

## Захтеви за адресе

### Само P2WPKH (SegWit v0)

**Операције ковања захтевају**:
- Bech32 кодиране адресе (почињу са „pocx1q" mainnet, „tpocx1q" testnet, „rpocx1q" regtest)
- P2WPKH (Pay-to-Witness-Public-Key-Hash) формат
- 20-бајтни хеш кључа

**НИЈЕ подржано**:
- P2PKH (legacy, почиње са „1")
- P2SH (wrapped SegWit, почиње са „3")
- P2TR (Taproot, почиње са „bc1p")

**Образложење**: PoCX потписи блокова захтевају специфичан witness v0 формат за валидацију доказа.

### Филтрирање падајућег менија адреса

**ComboBox адресе плота**:
- Аутоматски попуњен адресама за примање из новчаника
- Филтрира адресе које нису P2WPKH
- Приказује формат: „Ознака (адреса)" ако је означено, иначе само адреса
- Прва ставка: „-- Унесите прилагођену адресу --"Plot address must be segwit v0 (bech32)"
- „Адреса ковања мора бити P2WPKH (bech32)"
- „Неважећи формат адресе"
- „Нема монета на адреси плота. Не може доказати власништво."
- „Не може креирати трансакције са новчаником само за гледање"
- „Новчаник није доступан"
- „Новчаник закључан" (из RPC)

## Интеграција рударења

### Захтеви подешавања

**Конфигурација чвора**:
```bash
# bitcoin.conf
server=1
```

**Захтеви новчаника**:
- P2WPKH адресе за власништво над плотом
- Приватни кључеви за рударење (или адреса ковања ако користите додељивања)
- Потврђени UTXO-и за креирање трансакција

**Спољни алати**:
- `pocx_plotter`: Генериши плот датотеке
- `pocx_miner`: Скенирај плотове и шаљи nonce-ове

### Ток рада

#### Соло рударење

1. **Генериши плот датотеке**:
   ```bash
   pocx_plotter --account <plot_address_hash160> --seed <32_bytes> --nonces <count>
   ```

2. **Покрени чвор** са сервером за рударење:
   ```bash
   bitcoin-qt -server
   ```

3. **Конфигуриши рудар**:
   - Упери на RPC endpoint чвора
   - Наведи директоријуме плот датотека
   - Конфигуриши account ID (из адресе плота)

4. **Покрени рударење**:
   ```bash
   pocx_miner --rpc-url http://localhost:8332 --plots /path/to/plots
   ```

5. **Надгледај**:
   - Рудар позива `get_mining_info` сваки блок
   - Скенира плотове за најбољи рок
   - Позива `submit_nonce` када пронађе решење
   - Чвор валидира и аутоматски кује блок

#### Рударење у пулу

1. **Генериши плот датотеке** (исто као соло рударење)

2. **Креирај додељивање ковања**:
   - Отвори дијалог додељивања ковања
   - Изабери адресу плота
   - Унеси адресу ковања пула
   - Кликни „Пошаљи додељивање"
   - Сачекај кашњење активације (30 блокова testnet)

3. **Конфигуриши рудар**:
   - Упери на endpoint **пула** (не локални чвор)
   - Пул рукује `submit_nonce` ка ланцу

4. **Операција пула**:
   - Новчаник пула има приватне кључеве адресе ковања
   - Пул валидира слања од рудара
   - Пул позива `submit_nonce` ка блокчејну
   - Пул дистрибуира награде према политици пула

### Награде coinbase

**Без додељивања**:
- Coinbase плаћа директно адреси власника плота
- Проверите стање на адреси плота

**Са додељивањем**:
- Coinbase плаћа адреси ковања
- Пул прима награде
- Рудар прима удео од пула

**Распоред награда**:
- Почетно: 10 BTCX по блоку
- Преполовљавање: Сваких 1050000 блокова (~4 године)
- Распоред: 10 → 5 → 2.5 → 1.25 → ...

## Решавање проблема

### Уобичајени проблеми

#### „Новчаник нема приватни кључ за адресу плота"

**Узрок**: Новчаник не поседује адресу
**Решење**:
- Увезите приватни кључ преко `importprivkey` RPC
- Или користите другу адресу плота коју поседује новчаник

#### „Додељивање већ постоји за овај плот"

**Узрок**: Плот је већ додељен другој адреси
**Решење**:
1. Опозови постојеће додељивање
2. Сачекај кашњење опозива (720 блокова testnet)
3. Креирај ново додељивање

#### „Формат адресе није подржан"

**Узрок**: Адреса није P2WPKH bech32
**Решење**:
- Користите адресе које почињу са „pocx1q" (mainnet) или „tpocx1q" (testnet)
- Генеришите нову адресу ако је потребно: `getnewaddress "" "bech32"`

#### „Накнада трансакције премала"

**Узрок**: Загушење mempool-а мреже или накнада премала за релеј
**Решење**:
- Повећајте параметар стопе накнаде
- Сачекајте да се mempool очисти

#### „Додељивање још није активно"

**Узрок**: Кашњење активације још није истекло
**Решење**:
- Проверите статус: преостали блокови до активације
- Сачекајте да се период кашњења заврши

#### „Нема монета на адреси плота"

**Узрок**: Адреса плота нема потврђене UTXO-е
**Решење**:
1. Пошаљите средства на адресу плота
2. Сачекајте 1 потврду
3. Поново покушајте креирање додељивања

#### „Не може креирати трансакције са новчаником само за гледање"

**Узрок**: Новчаник је увезао адресу без приватног кључа
**Решење**: Увезите комплетан приватни кључ, не само адресу

#### „Картица додељивања ковања није видљива"

**Узрок**: Чвор покренут без `` флага
**Решење**: Рестартујте са `bitcoin-qt -server`

### Кораци за дебаговање

1. **Проверите статус новчаника**:
   ```bash
   bitcoin-cli getwalletinfo
   ```

2. **Верификујте власништво над адресом**:
   ```bash
   bitcoin-cli getaddressinfo pocx1qplot...
   # Проверите: "iswatchonly": false, "ismine": true
   ```

3. **Проверите статус додељивања**:
   ```bash
   bitcoin-cli get_assignment pocx1qplot...
   ```

4. **Прегледајте недавне трансакције**:
   ```bash
   bitcoin-cli listtransactions "*" 10
   ```

5. **Проверите синхронизацију чвора**:
   ```bash
   bitcoin-cli getblockchaininfo
   # Верификујте: blocks == headers (потпуно синхронизовано)
   ```

## Најбоље безбедносне праксе

### Безбедност адресе плота

**Управљање кључевима**:
- Безбедно чувајте приватне кључеве адресе плота
- Трансакције додељивања доказују власништво путем потписа
- Само власник плота може креирати/опозивати додељивања

**Резервна копија**:
- Редовно правите резервну копију новчаника (`dumpwallet` или `backupwallet`)
- Чувајте wallet.dat на безбедној локацији
- Забележите фразе за опоравак ако користите HD новчаник

### Делегирање адресе ковања

**Безбедносни модел**:
- Адреса ковања прима награде блокова
- Адреса ковања може потписивати блокове (рударење)
- Адреса ковања **НЕ МОЖЕ** модификовати или опозивати додељивање
- Власник плота задржава потпуну контролу

**Случајеви употребе**:
- **Делегирање hot wallet-а**: Кључ плота у хладном складиштењу, кључ ковања у hot wallet-у за рударење
- **Рударење у пулу**: Делегирај пулу, задржи власништво над плотом
- **Дељена инфраструктура**: Више рудара, једна адреса ковања

### Синхронизација мрежног времена

**Важност**:
- PoCX консензус захтева тачно време
- Одступање сата >10s покреће упозорење
- Одступање сата >15s спречава рударење

**Решење**:
- Одржавајте системски сат синхронизован са NTP
- Надгледајте: `bitcoin-cli getnetworkinfo` за упозорења о временском офсету
- Користите поуздане NTP сервере

### Кашњења додељивања

**Кашњење активације** (30 блокова testnet):
- Спречава брзо поновно додељивање током вилица ланца
- Дозвољава мрежи да достигне консензус
- Не може се заобићи

**Кашњење опозива** (720 блокова testnet):
- Обезбеђује стабилност за пулове за рударење
- Спречава нападе „скакања додељивања"
- Адреса ковања остаје активна током кашњења

### Шифровање новчаника

**Омогућите шифровање**:
```bash
bitcoin-cli encryptwallet "your_passphrase"
```

**Откључајте за трансакције**:
```bash
bitcoin-cli walletpassphrase "your_passphrase" 300
```

**Најбоље праксе**:
- Користите јаку лозинку (20+ карактера)
- Не чувајте лозинку у обичном тексту
- Закључајте новчаник након креирања додељивања
