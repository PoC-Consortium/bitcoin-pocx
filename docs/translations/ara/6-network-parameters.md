## معلمات كتلة التكوين

### حساب الهدف الأساسي

**الصيغة**: `genesis_base_target = 2^42 / block_time_seconds`

**المبررات**:
- كل nonce يمثل 256 KiB (64 بايت × 4096 scoops)
- 1 TiB = 2^22 nonces (افتراض سعة الشبكة الأولية)
- الجودة الأدنى المتوقعة لـ n nonces ≈ 2^64 / n
- لـ 1 TiB: E(quality) = 2^64 / 2^22 = 2^42
- لذلك: base_target = 2^42 / block_time

**القيم المحسوبة**:
- Mainnet/Testnet/Signet (120 ثانية): `36650387592`
- Regtest (1 ثانية): يستخدم وضع معايرة السعة المنخفضة

### رسالة التكوين

Each network has its own genesis message. See `src/kernel/chainparams.cpp` for details.

## معلمات الإجماع

### معلمات التوقيت

**MAX_FUTURE_BLOCK_TIME**: `15` ثانية
- خاص بـ PoCX (Bitcoin يستخدم 2 ساعة)
- المبررات: توقيت PoC يتطلب تحققاً شبه فوري
- الكتل أكثر من 15 ثانية في المستقبل تُرفض

**عتبة تحذير إزاحة الوقت**: `10` ثوانٍ
- يُحذّر المشغّلين عندما تنحرف ساعة العقدة >10 ثوانٍ عن وقت الشبكة
- لا إنفاذ، معلوماتي فقط

**أهداف وقت الكتلة**:
- Mainnet/Testnet/Signet: `120` ثانية
- Regtest: `1` ثانية

**TIMESTAMP_WINDOW**: `15` ثانية (يساوي MAX_FUTURE_BLOCK_TIME)

**التنفيذ**: `src/chain.h`، `src/validation.cpp`

### معلمات تعديل الصعوبة

**حجم النافذة المتدحرجة**: `24` كتلة (جميع الشبكات)
- المتوسط المتحرك الأسي لأوقات الكتل الأخيرة
- تعديل كل كتلة
- استجابة لتغييرات السعة

**التنفيذ**: `src/consensus/params.h`، منطق الصعوبة في إنشاء الكتلة

### معلمات نظام التعيين

**nForgingAssignmentDelay** (تأخير التفعيل):
- Mainnet: `30` كتلة (~1 ساعة)
- Testnet: `30` كتلة (~1 ساعة)
- Regtest: `4` كتل (~4 ثوانٍ)

**nForgingRevocationDelay** (تأخير الإلغاء):
- Mainnet: `720` كتلة (~24 ساعة)
- Testnet: `720` كتلة (~24 ساعة)
- Regtest: `8` كتل (~8 ثوانٍ)

**المبررات**:
- تأخير التفعيل يمنع إعادة التعيين السريعة أثناء سباقات الكتل
- تأخير الإلغاء يوفر الاستقرار ويمنع الإساءة

**التنفيذ**: `src/consensus/params.h`

## Coinbase ومكافآت الكتل

### جدول إعانة الكتلة

**الإعانة الأولية**: `10 BTC` (جميع الشبكات)

**جدول التنصيف**:
- كل `1050000` كتلة (mainnet/testnet)
- كل `500` كتلة (regtest)
- يستمر لـ 64 تنصيف كحد أقصى

**تقدم التنصيف**:
```
التنصيف 0: 10.00000000 BTC  (الكتل 0 - 1049999)
التنصيف 1:  5.00000000 BTC  (الكتل 1050000 - 2099999)
التنصيف 2:  2.50000000 BTC  (الكتل 2100000 - 3149999)
التنصيف 3:  1.25000000 BTC  (الكتل 3150000 - 4199999)
...
```

**إجمالي العرض**: ~21 مليون BTC (نفس Bitcoin)

### قواعد مخرج Coinbase

**وجهة الدفع**:
- **بدون تعيين**: Coinbase يدفع لعنوان الرسم (proof.account_id)
- **مع تعيين**: Coinbase يدفع لعنوان الصياغة (المُوقّع الفعال)

**صيغة المخرج**: P2WPKH فقط
- Coinbase يجب أن يدفع لعنوان bech32 SegWit v0
- يُولّد من المفتاح العام للمُوقّع الفعال

**حل التعيين**:
```cpp
effective_signer = GetEffectiveSigner(plot_address, height, view);
coinbase_script = P2WPKH(effective_signer);
```

**التنفيذ**: `src/pocx/mining/block_builder.cpp:BuildBlock()`

## المقياس الديناميكي

### حدود المقياس

**الغرض**: زيادة صعوبة توليد الرسم مع نضوج الشبكة لمنع تضخم السعة

**الهيكل**:
```cpp
struct PoCXCompressionBounds {
    uint32_t nPoCXMinCompression;     // الحد الأدنى المقبول
    uint32_t nPoCXTargetCompression;  // المستوى الموصى به
};
```

**العلاقة**: `target = min + 1` (دائماً مستوى واحد فوق الحد الأدنى)

### جدول زيادة المقياس

مستويات المقياس تزداد وفق **جدول أسي** بناءً على فترات التنصيف:

| الفترة الزمنية | ارتفاع الكتلة | التنصيفات | الأدنى | المستهدف |
|-------------|--------------|----------|-----|--------|
| السنوات 0-4 | 0 إلى 1049999 | 0 | X1 | X2 |
| السنوات 4-12 | 1050000 إلى 3149999 | 1-2 | X2 | X3 |
| السنوات 12-28 | 3150000 إلى 7349999 | 3-6 | X3 | X4 |
| السنوات 28-60 | 7350000 إلى 15749999 | 7-14 | X4 | X5 |
| السنوات 60-124 | 15750000 إلى 32549999 | 15-30 | X5 | X6 |
| السنوات 124+ | 32550000+ | 31+ | X6 | X7 |

**الارتفاعات الرئيسية** (السنوات → التنصيفات → الكتل):
- السنة 4: التنصيف 1 عند الكتلة 1050000
- السنة 12: التنصيف 3 عند الكتلة 3150000
- السنة 28: التنصيف 7 عند الكتلة 7350000
- السنة 60: التنصيف 15 عند الكتلة 15750000
- السنة 124: التنصيف 31 عند الكتلة 32550000

### صعوبة مستوى المقياس

**مقياس PoW**:
- مستوى المقياس X0: خط أساس POC2 (نظري)
- مستوى المقياس X1: خط أساس XOR-transpose
- مستوى المقياس Xn: 2^(n-1) × عمل X1 مضمّن
- كل مستوى يُضاعف عمل توليد الرسم

**المحاذاة الاقتصادية**:
- مكافآت الكتل تتنصف → صعوبة توليد الرسم تزداد
- يحافظ على هامش الأمان: تكلفة إنشاء الرسم > تكلفة البحث
- يمنع تضخم السعة من تحسينات الأجهزة

### التحقق من الرسم

**قواعد التحقق**:
- الإثباتات المُرسلة يجب أن يكون مستوى مقياسها ≥ الحد الأدنى
- الإثباتات بمقياس > المستهدف مقبولة لكن غير فعالة
- الإثباتات تحت الحد الأدنى: مرفوضة (PoW غير كافٍ)

**استرجاع الحدود**:
```cpp
auto bounds = GetPoCXCompressionBounds(height, halving_interval);
```

**التنفيذ**: `src/pocx/consensus/params.h:GetPoCXCompressionBounds()`، `src/pocx/consensus/params.cpp`

## هيكل مجلد البيانات

### المجلد الافتراضي

**الموقع**: `.bitcoin/` (نفس Bitcoin Core)
- Linux: `~/.bitcoin/`
- macOS: `~/Library/Application Support/Bitcoin/`
- Windows: `%APPDATA%\Bitcoin\`

### محتويات المجلد

```
.bitcoin/
├── blocks/              # بيانات الكتل
│   ├── blk*.dat        # ملفات الكتل
│   ├── rev*.dat        # بيانات التراجع
│   └── index/          # فهرس الكتل (LevelDB)
├── chainstate/         # مجموعة UTXO + تعيينات الصياغة (LevelDB)
├── wallets/            # ملفات المحفظة
│   └── wallet.dat      # المحفظة الافتراضية
├── bitcoin.conf        # ملف التكوين
├── debug.log           # سجل التصحيح
├── peers.dat           # عناوين الأقران
├── mempool.dat         # استمرارية mempool
└── banlist.dat         # الأقران المحظورين
```

### الاختلافات الرئيسية عن Bitcoin

**قاعدة بيانات Chainstate**:
- قياسي: مجموعة UTXO
- **إضافة PoCX**: حالة تعيين الصياغة
- تحديثات ذرية: UTXO + التعيينات تُحدّث معاً
- بيانات تراجع آمنة من إعادة التنظيم للتعيينات

**ملفات الكتل**:
- صيغة كتلة Bitcoin القياسية
- **إضافة PoCX**: موسّعة بحقول إثبات PoCX (account_id، seed، nonce، signature، pubkey)

### مثال ملف التكوين

**bitcoin.conf**:
```ini
# اختيار الشبكة
#testnet=1
#regtest=1

# خادم تعدين PoCX (مطلوب للمُعدّنين الخارجيين)

# إعدادات RPC
server=1
rpcuser=yourusername
rpcpassword=yourpassword
rpcallowip=127.0.0.1
rpcport=8332

# إعدادات الاتصال
listen=1
port=8338
maxconnections=125

# هدف وقت الكتلة (معلوماتي، الإجماع يُنفذ)
# 120 ثانية لـ mainnet/testnet
```
