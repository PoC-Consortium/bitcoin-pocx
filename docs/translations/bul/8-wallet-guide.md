## Преглед

### Функции на портфейла Bitcoin-PoCX

Qt портфейлът на Bitcoin-PoCX (`bitcoin-qt`) предоставя:
- Стандартна функционалност на Bitcoin Core портфейл (изпращане, получаване, управление на транзакции)
- **Мениджър за делегиране на подписване**: GUI за създаване/отмяна на делегирания на plot
- **Режим Mining сървър**: флаг `` активира функции, свързани с копаене
- **История на транзакции**: Показване на транзакции за делегиране и отмяна

### Стартиране на портфейла

**Само възел** (без копаене):
```bash
./build/bin/bitcoin-qt
```

**С копаене** (активира диалог за делегиране):
```bash
./build/bin/bitcoin-qt -server
```

**Алтернатива на командния ред**:
```bash
./build/bin/bitcoind
```

### Изисквания за копаене

**За операции по копаене**:
- Изисква се флаг ``
- Портфейл с P2WPKH адреси и частни ключове
- Външен plotter (`pocx_plotter`) за генериране на plot
- Външен miner (`pocx_miner`) за копаене

**За копаене в пул**:
- Създайте делегиране към адрес на пула
- Не се изисква портфейл на pool сървъра (пулът управлява ключовете)

## Диалог за делегиране на подписване

### Достъп до диалога

**Меню**: `Портфейл → Делегиране на подписване`
**Лента с инструменти**: Икона за копаене (видима само с флаг ``)
**Размер на прозореца**: 600×450 пиксела

### Режими на диалога

#### Режим 1: Създаване на делегиране

**Цел**: Делегиране на права за подписване на пул или друг адрес, като се запазва собствеността върху plot.

**Случаи на употреба**:
- Копаене в пул (делегиране към адрес на пула)
- Студено съхранение (ключ за копаене отделен от собственост върху plot)
- Споделена инфраструктура (делегиране към горещ портфейл)

**Изисквания**:
- Адрес на plot (P2WPKH bech32, трябва да притежавате частен ключ)
- Адрес за подписване (P2WPKH bech32, различен от адреса на plot)
- Портфейл отключен (ако е криптиран)
- Адресът на plot има потвърдени UTXO

**Стъпки**:
1. Изберете режим "Създаване на делегиране"
2. Изберете адрес на plot от падащото меню или въведете ръчно
3. Въведете адрес за подписване (пул или делегат)
4. Кликнете "Изпращане на делегиране" (бутон активен, когато входовете са валидни)
5. Транзакцията се разпространява незабавно
6. Делегирането е активно след `nForgingAssignmentDelay` блока:
   - Mainnet/Testnet: 30 блока (~1 час)
   - Regtest: 4 блока (~8 минути при разстояние 120s)

**Такса за транзакция**: По подразбиране 10× `minRelayFee` (настройваема)

**Структура на транзакция**:
- Вход: UTXO от адрес на plot (доказва собственост)
- OP_RETURN изход (46-байтов скрипт, 44-байтов полезен товар): `POCX` маркер + plot_address + forging_address
- Изход за ресто: Върнат в портфейла

#### Режим 2: Отмяна на делегиране

**Цел**: Отмяна на делегиране и връщане на права на собственика на plot.

**Изисквания**:
- Адрес на plot (трябва да притежавате частен ключ)
- Портфейл отключен (ако е криптиран)
- Адресът на plot има потвърдени UTXO

**Стъпки**:
1. Изберете режим "Отмяна на делегиране"
2. Изберете адрес на plot
3. Кликнете "Изпращане на отмяна"
4. Транзакцията се разпространява незабавно
5. Отмяната влиза в сила след `nForgingRevocationDelay` блока:
   - Mainnet/Testnet: 720 блока (~24 часа)
   - Regtest: 8 блока (~16 минути при разстояние 120s)

**Ефект**:
- Адресът за подписване все още може да подписва по време на периода на забавяне
- Собственикът на plot възстановява права след завършване на отмяната
- Може да създаде ново делегиране след това

**Структура на транзакция**:
- Вход: UTXO от адрес на plot (доказва собственост)
- OP_RETURN изход (26-байтов скрипт, 24-байтов полезен товар): `XCOP` маркер + plot_address
- Изход за ресто: Върнат в портфейла

#### Режим 3: Проверка на статус на делегиране

**Цел**: Заявка за текущо състояние на делегиране за произволен адрес на plot.

**Изисквания**: Няма (само за четене, не изисква портфейл)

**Стъпки**:
1. Изберете режим "Проверка на статус на делегиране"
2. Въведете адрес на plot
3. Кликнете "Проверка на статус"
4. Кутията за статус показва текущо състояние с детайли

**Индикатори за състояние** (цветно кодирани):

**Сиво — UNASSIGNED**
```
UNASSIGNED — Няма делегиране
```

**Оранжево — ASSIGNING**
```
ASSIGNING — Делегиране в очакване на активиране
Адрес за подписване: pocx1qforger...
Създадено на височина: 12000
Активира се на височина: 12030 (5 блока остават)
```

**Зелено — ASSIGNED**
```
ASSIGNED — Активно делегиране
Адрес за подписване: pocx1qforger...
Създадено на височина: 12000
Активирано на височина: 12030
```

**Червено-оранжево — REVOKING**
```
REVOKING — Отмяна в очакване
Адрес за подписване: pocx1qforger... (все още активен)
Делегиране създадено на височина: 12000
Отменено на височина: 12300
Отмяна влиза в сила на височина: 13020 (50 блока остават)
```

**Червено — REVOKED**
```
REVOKED — Делегиране отменено
Предишно делегиран на: pocx1qforger...
Делегиране създадено на височина: 12000
Отменено на височина: 12300
Отмяна в сила от височина: 13020
```

## История на транзакции

### Показване на транзакция за делегиране

**Тип**: "Assignment"
**Икона**: Икона за копаене (същата като добити блокове)

**Колона Адрес**: Адрес на plot (адресът, чиито права за подписване се делегират)
**Колона Сума**: Такса за транзакция (отрицателна, изходяща транзакция)
**Колона Статус**: Брой потвърждения (0-6+)

**Детайли** (при кликване):
- ID на транзакция
- Адрес на plot
- Адрес за подписване (парсиран от OP_RETURN)
- Създаден на височина
- Височина на активиране
- Такса за транзакция
- Времева марка

### Показване на транзакция за отмяна

**Тип**: "Revocation"
**Икона**: Икона за копаене

**Колона Адрес**: Адрес на plot
**Колона Сума**: Такса за транзакция (отрицателна)
**Колона Статус**: Брой потвърждения

**Детайли** (при кликване):
- ID на транзакция
- Адрес на plot
- Отменено на височина
- Височина на влизане в сила на отмяна
- Такса за транзакция
- Времева марка

### Филтриране на транзакции

**Налични филтри**:
- "Всички" (по подразбиране, включва делегирания/отмяни)
- Диапазон на дати
- Диапазон на суми
- Търсене по адрес
- Търсене по ID на транзакция
- Търсене по етикет (ако адресът е етикетиран)

**Забележка**: Транзакциите за делегиране/отмяна понастоящем се появяват под филтър "Всички". Специализиран филтър за тип все още не е имплементиран.

### Сортиране на транзакции

**Ред на сортиране** (по тип):
- Generated (тип 0)
- Received (тип 1-3)
- Assignment (тип 4)
- Revocation (тип 5)
- Sent (тип 6+)

## Изисквания за адреси

### Само P2WPKH (SegWit v0)

**Операциите за подписване изискват**:
- Bech32 кодирани адреси (започващи с "pocx1q" mainnet, "tpocx1q" testnet, "rpocx1q" regtest)
- P2WPKH (Pay-to-Witness-Public-Key-Hash) формат
- 20-байтов ключов хеш

**НЕ СЕ поддържат**:
- P2PKH (legacy, започващ с "1")
- P2SH (wrapped SegWit, започващ с "3")
- P2TR (Taproot, започващ с "bc1p")

**Обосновка**: PoCX подписите на блокове изискват специфичен witness v0 формат за валидация на доказателство.

### Филтриране на падащо меню за адреси

**ComboBox за адрес на plot**:
- Автоматично попълнен с адресите за получаване на портфейла
- Филтрира не-P2WPKH адреси
- Показва формат: "Етикет (адрес)" ако е етикетиран, иначе само адрес
- Първи елемент: "-- Въведете персонализиран адрес --" за ръчно въвеждане

**Ръчно въвеждане**:
- Валидира формат при въвеждане
- Трябва да бъде валиден bech32 P2WPKH
- Бутон деактивиран ако форматът е невалиден

### Съобщения за грешка при валидация

**Грешки в диалога**:
- "Plot address must be segwit v0 (bech32)"
- "Адресът за подписване трябва да бъде P2WPKH (bech32)"
- "Невалиден формат на адрес"
- "Няма налични монети на адреса на plot. Не може да се докаже собственост."
- "Не могат да се създават транзакции с watch-only портфейл"
- "Портфейлът не е наличен"
- "Портфейлът е заключен" (от RPC)

## Интеграция на копаене

### Изисквания за настройка

**Конфигурация на възел**:
```bash
# bitcoin.conf
server=1
```

**Изисквания за портфейл**:
- P2WPKH адреси за собственост върху plot
- Частни ключове за копаене (или адрес за подписване ако се използват делегирания)
- Потвърдени UTXO за създаване на транзакции

**Външни инструменти**:
- `pocx_plotter`: Генериране на plot файлове
- `pocx_miner`: Сканиране на plot файлове и подаване на nonces

### Работен поток

#### Соло копаене

1. **Генериране на Plot файлове**:
   ```bash
   pocx_plotter --account <plot_address_hash160> --seed <32_bytes> --nonces <count>
   ```

2. **Стартиране на възел** с mining сървър:
   ```bash
   bitcoin-qt -server
   ```

3. **Конфигуриране на Miner**:
   - Посочете RPC endpoint на възела
   - Укажете директории с plot файлове
   - Конфигурирайте account ID (от адрес на plot)

4. **Стартиране на копаене**:
   ```bash
   pocx_miner --rpc-url http://localhost:8332 --plots /path/to/plots
   ```

5. **Наблюдение**:
   - Miner извиква `get_mining_info` всеки блок
   - Сканира plot файлове за най-добър краен срок
   - Извиква `submit_nonce` когато намери решение
   - Възелът валидира и подписва блок автоматично

#### Копаене в пул

1. **Генериране на Plot файлове** (същото като соло копаене)

2. **Създаване на делегиране**:
   - Отворете диалог за делегиране
   - Изберете адрес на plot
   - Въведете адреса за подписване на пула
   - Кликнете "Изпращане на делегиране"
   - Изчакайте забавяне на активиране (30 блока testnet)

3. **Конфигуриране на Miner**:
   - Посочете endpoint на **пула** (не локален възел)
   - Пулът обработва `submit_nonce` към веригата

4. **Операция на пул**:
   - Портфейлът на пула има частни ключове за адреса за подписване
   - Пулът валидира подавания от миньори
   - Пулът извиква `submit_nonce` към блокчейна
   - Пулът разпределя награди според политика на пула

### Coinbase награди

**Без делегиране**:
- Coinbase плаща директно на адреса на собственика на plot
- Проверете баланс в адреса на plot

**С делегиране**:
- Coinbase плаща на адреса за подписване
- Пулът получава наградите
- Миньорът получава дял от пула

**График на награди**:
- Начално: 10 BTCX на блок
- Halving: На всеки 1050000 блока (~4 години)
- График: 10 → 5 → 2.5 → 1.25 → ...

## Отстраняване на проблеми

### Често срещани проблеми

#### "Портфейлът няма частен ключ за адреса на plot"

**Причина**: Портфейлът не притежава адреса
**Решение**:
- Импортирайте частен ключ чрез `importprivkey` RPC
- Или използвайте различен адрес на plot, притежаван от портфейла

#### "Вече съществува делегиране за този plot"

**Причина**: Plot вече е делегиран на друг адрес
**Решение**:
1. Отменете съществуващото делегиране
2. Изчакайте забавяне на отмяна (720 блока testnet)
3. Създайте ново делегиране

#### "Форматът на адреса не се поддържа"

**Причина**: Адресът не е P2WPKH bech32
**Решение**:
- Използвайте адреси, започващи с "pocx1q" (mainnet) или "tpocx1q" (testnet)
- Генерирайте нов адрес ако е необходимо: `getnewaddress "" "bech32"`

#### "Такса за транзакция е твърде ниска"

**Причина**: Претоварване на mempool или такса твърде ниска за relay
**Решение**:
- Увеличете параметъра за такса
- Изчакайте изчистване на mempool

#### "Делегирането все още не е активно"

**Причина**: Забавянето на активиране все още не е изтекло
**Решение**:
- Проверете статус: оставащи блокове до активиране
- Изчакайте периода на забавяне да завърши

#### "Няма налични монети на адреса на plot"

**Причина**: Адресът на plot няма потвърдени UTXO
**Решение**:
1. Изпратете средства към адреса на plot
2. Изчакайте 1 потвърждение
3. Опитайте отново създаване на делегиране

#### "Не могат да се създават транзакции с watch-only портфейл"

**Причина**: Портфейлът е импортирал адрес без частен ключ
**Решение**: Импортирайте пълен частен ключ, не само адрес

#### "Табът за делегиране не е видим"

**Причина**: Възелът е стартиран без флаг ``
**Решение**: Рестартирайте с `bitcoin-qt -server`

### Стъпки за дебъгване

1. **Проверка на статус на портфейл**:
   ```bash
   bitcoin-cli getwalletinfo
   ```

2. **Проверка на собственост на адрес**:
   ```bash
   bitcoin-cli getaddressinfo pocx1qplot...
   # Проверете: "iswatchonly": false, "ismine": true
   ```

3. **Проверка на статус на делегиране**:
   ```bash
   bitcoin-cli get_assignment pocx1qplot...
   ```

4. **Преглед на последни транзакции**:
   ```bash
   bitcoin-cli listtransactions "*" 10
   ```

5. **Проверка на синхронизация на възел**:
   ```bash
   bitcoin-cli getblockchaininfo
   # Проверете: blocks == headers (напълно синхронизиран)
   ```

## Най-добри практики за сигурност

### Сигурност на адреса на plot

**Управление на ключове**:
- Съхранявайте частни ключове на адреса на plot сигурно
- Транзакциите за делегиране доказват собственост чрез подпис
- Само собственикът на plot може да създава/отменя делегирания

**Резервно копие**:
- Създавайте редовно резервни копия на портфейла (`dumpwallet` или `backupwallet`)
- Съхранявайте wallet.dat на сигурно място
- Записвайте фрази за възстановяване ако използвате HD портфейл

### Делегиране на адрес за подписване

**Модел на сигурност**:
- Адресът за подписване получава награди за блок
- Адресът за подписване може да подписва блокове (копаене)
- Адресът за подписване **НЕ МОЖЕ** да модифицира или отменя делегиране
- Собственикът на plot запазва пълен контрол

**Случаи на употреба**:
- **Делегиране на горещ портфейл**: Ключ на plot в студено съхранение, ключ за подписване в горещ портфейл за копаене
- **Копаене в пул**: Делегиране към пул, запазване на собственост върху plot
- **Споделена инфраструктура**: Множество миньори, един адрес за подписване

### Синхронизация на мрежово време

**Важност**:
- Консенсусът на PoCX изисква точно време
- Отклонение на часовника >10s задейства предупреждение
- Отклонение на часовника >15s предотвратява копаене

**Решение**:
- Поддържайте системния часовник синхронизиран с NTP
- Наблюдавайте: `bitcoin-cli getnetworkinfo` за предупреждения за отклонение на време
- Използвайте надеждни NTP сървъри

### Забавяния на делегиране

**Забавяне на активиране** (30 блока testnet):
- Предотвратява бързо пределегиране при разклонения на веригата
- Позволява на мрежата да достигне консенсус
- Не може да бъде заобиколено

**Забавяне на отмяна** (720 блока testnet):
- Предоставя стабилност за mining пулове
- Предотвратява атаки с "griefing" на делегиране
- Адресът за подписване остава активен по време на забавяне

### Криптиране на портфейл

**Активиране на криптиране**:
```bash
bitcoin-cli encryptwallet "your_passphrase"
```

**Отключване за транзакции**:
```bash
bitcoin-cli walletpassphrase "your_passphrase" 300
```

**Най-добри практики**:
- Използвайте силна парола (20+ символа)
- Не съхранявайте паролата в обикновен текст
- Заключвайте портфейла след създаване на делегирания
