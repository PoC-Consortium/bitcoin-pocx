## Огляд

### Функції гаманця Bitcoin-PoCX

Qt-гаманець Bitcoin-PoCX (`bitcoin-qt`) надає:
- Стандартну функціональність гаманця Bitcoin Core (надсилання, отримання, управління транзакціями)
- **Менеджер призначень кування**: GUI для створення/скасування призначень плотів
- **Режим сервера майнінгу**: Прапорець `` вмикає функції, пов'язані з майнінгом
- **Історія транзакцій**: Відображення транзакцій призначень та скасувань

### Запуск гаманця

**Тільки вузол** (без майнінгу):
```bash
./build/bin/bitcoin-qt
```

**З майнінгом** (вмикає діалог призначень):
```bash
./build/bin/bitcoin-qt -server
```

**Альтернатива командного рядка**:
```bash
./build/bin/bitcoind
```

### Вимоги для майнінгу

**Для операцій майнінгу**:
- Прапорець `` обов'язковий
- Гаманець з адресами P2WPKH та приватними ключами
- Зовнішній плотер (`pocx_plotter`) для генерації плотів
- Зовнішній майнер (`pocx_miner`) для майнінгу

**Для пул-майнінгу**:
- Створіть призначення кування на адресу пулу
- Гаманець не потрібен на сервері пулу (пул управляє ключами)

## Одиниці валюти

### Відображення одиниць

Bitcoin-PoCX використовує одиницю валюти **BTCX** (не BTC):

| Одиниця | Сатоші | Відображення |
|---------|--------|--------------|
| **BTCX** | 100000000 | 1.00000000 BTCX |
| **mBTCX** | 100000 | 1000.00 mBTCX |
| **µBTCX** | 100 | 1000000.00 µBTCX |
| **сатоші** | 1 | 100000000 sat |

**Налаштування GUI**: Параметри → Відображення → Одиниця

## Діалог призначення кування

### Доступ до діалогу

**Меню**: `Гаманець → Призначення кування`
**Панель інструментів**: Іконка майнінгу (видима лише з прапорцем ``)
**Розмір вікна**: 600×450 пікселів

### Режими діалогу

#### Режим 1: Створення призначення

**Призначення**: Делегування прав кування пулу або іншій адресі зі збереженням володіння плотом.

**Випадки використання**:
- Пул-майнінг (призначення на адресу пулу)
- Холодне зберігання (ключ майнінгу окремо від володіння плотом)
- Спільна інфраструктура (делегування на гарячий гаманець)

**Вимоги**:
- Адреса плоту (P2WPKH bech32, повинен володіти приватним ключем)
- Адреса кування (P2WPKH bech32, відмінна від адреси плоту)
- Гаманець розблокований (якщо зашифрований)
- Адреса плоту має підтверджені UTXO

**Кроки**:
1. Виберіть режим "Створити призначення"
2. Виберіть адресу плоту з випадаючого списку або введіть вручну
3. Введіть адресу кування (пул або делегат)
4. Натисніть "Надіслати призначення" (кнопка активна коли введення валідне)
5. Транзакція транслюється негайно
6. Призначення активне після `nForgingAssignmentDelay` блоків:
   - Mainnet/Testnet: 30 блоків (~1 година)
   - Regtest: 4 блоки (~4 секунди)

**Комісія транзакції**: За замовчуванням 10× `minRelayFee` (настроюється)

**Структура транзакції**:
- Вхід: UTXO з адреси плоту (доводить володіння)
- Вихід OP_RETURN: маркер `POCX` + plot_address + forging_address (46 байтів)
- Вихід решти: Повертається до гаманця

#### Режим 2: Скасування призначення

**Призначення**: Скасування призначення кування та повернення прав власнику плоту.

**Вимоги**:
- Адреса плоту (повинен володіти приватним ключем)
- Гаманець розблокований (якщо зашифрований)
- Адреса плоту має підтверджені UTXO

**Кроки**:
1. Виберіть режим "Скасувати призначення"
2. Виберіть адресу плоту
3. Натисніть "Надіслати скасування"
4. Транзакція транслюється негайно
5. Скасування набуває чинності після `nForgingRevocationDelay` блоків:
   - Mainnet/Testnet: 720 блоків (~24 години)
   - Regtest: 8 блоків (~8 секунд)

**Ефект**:
- Адреса кування все ще може кувати під час періоду затримки
- Власник плоту відновлює права після завершення скасування
- Можна створити нове призначення після цього

**Структура транзакції**:
- Вхід: UTXO з адреси плоту (доводить володіння)
- Вихід OP_RETURN: маркер `XCOP` + plot_address (26 байтів)
- Вихід решти: Повертається до гаманця

#### Режим 3: Перевірка статусу призначення

**Призначення**: Запит поточного стану призначення для будь-якої адреси плоту.

**Вимоги**: Немає (тільки для читання, гаманець не потрібен)

**Кроки**:
1. Виберіть режим "Перевірити статус призначення"
2. Введіть адресу плоту
3. Натисніть "Перевірити статус"
4. Поле статусу відображає поточний стан з деталями

**Індикатори стану** (кольорово-кодовані):

**Сірий - UNASSIGNED**
```
UNASSIGNED - Призначення не існує
```

**Помаранчевий - ASSIGNING**
```
ASSIGNING - Призначення очікує активації
Адреса кування: pocx1qforger...
Створено на висоті: 12000
Активується на висоті: 12030 (залишилося 5 блоків)
```

**Зелений - ASSIGNED**
```
ASSIGNED - Активне призначення
Адреса кування: pocx1qforger...
Створено на висоті: 12000
Активовано на висоті: 12030
```

**Червоно-помаранчевий - REVOKING**
```
REVOKING - Скасування очікує
Адреса кування: pocx1qforger... (ще активна)
Призначення створено на висоті: 12000
Скасовано на висоті: 12300
Скасування набуває чинності на висоті: 13020 (залишилося 50 блоків)
```

**Червоний - REVOKED**
```
REVOKED - Призначення скасовано
Раніше призначено до: pocx1qforger...
Призначення створено на висоті: 12000
Скасовано на висоті: 12300
Скасування набуло чинності на висоті: 13020
```

## Історія транзакцій

### Відображення транзакцій призначень

**Тип**: "Призначення"
**Іконка**: Іконка майнінгу (така ж як видобуті блоки)

**Колонка адреси**: Адреса плоту (адреса, права кування якої призначаються)
**Колонка суми**: Комісія транзакції (від'ємна, вихідна транзакція)
**Колонка статусу**: Кількість підтверджень (0-6+)

**Деталі** (при натисканні):
- ID транзакції
- Адреса плоту
- Адреса кування (розпарсена з OP_RETURN)
- Створено на висоті
- Висота активації
- Комісія транзакції
- Мітка часу

### Відображення транзакцій скасування

**Тип**: "Скасування"
**Іконка**: Іконка майнінгу

**Колонка адреси**: Адреса плоту
**Колонка суми**: Комісія транзакції (від'ємна)
**Колонка статусу**: Кількість підтверджень

**Деталі** (при натисканні):
- ID транзакції
- Адреса плоту
- Скасовано на висоті
- Висота набуття чинності скасування
- Комісія транзакції
- Мітка часу

### Фільтрація транзакцій

**Доступні фільтри**:
- "Усі" (за замовчуванням, включає призначення/скасування)
- Діапазон дат
- Діапазон сум
- Пошук за адресою
- Пошук за ID транзакції
- Пошук за міткою (якщо адреса має мітку)

**Примітка**: Транзакції призначень/скасувань наразі з'являються під фільтром "Усі". Окремий фільтр за типом ще не реалізовано.

### Сортування транзакцій

**Порядок сортування** (за типом):
- Згенеровані (тип 0)
- Отримані (тип 1-3)
- Призначення (тип 4)
- Скасування (тип 5)
- Надіслані (тип 6+)

## Вимоги до адрес

### Тільки P2WPKH (SegWit v0)

**Операції кування вимагають**:
- Адреси, закодовані в bech32 (починаються з "pocx1q" mainnet, "tpocx1q" testnet, "rpocx1q" regtest)
- Формат P2WPKH (Pay-to-Witness-Public-Key-Hash)
- 20-байтовий хеш ключа

**НЕ підтримуються**:
- P2PKH (legacy, починаються з "1")
- P2SH (wrapped SegWit, починаються з "3")
- P2TR (Taproot, починаються з "bc1p")

**Обґрунтування**: Підписи блоків PoCX вимагають специфічного формату witness v0 для валідації доказу.

### Фільтрація випадаючого списку адрес

**ComboBox адреси плоту**:
- Автоматично заповнюється адресами отримання гаманця
- Фільтрує адреси не-P2WPKH
- Показує формат: "Мітка (адреса)" якщо є мітка, інакше лише адреса
- Перший елемент: "-- Введіть власну адресу --" для ручного введення

**Ручне введення**:
- Валідує формат при введенні
- Повинен бути валідним bech32 P2WPKH
- Кнопка вимкнена якщо невалідний формат

### Повідомлення про помилки валідації

**Помилки діалогу**:
- "Plot address must be segwit v0 (bech32)"
- "Адреса кування повинна бути P2WPKH (bech32)"
- "Невалідний формат адреси"
- "Немає монет на адресі плоту. Неможливо довести володіння."
- "Неможливо створювати транзакції з гаманцем тільки для перегляду"
- "Гаманець недоступний"
- "Гаманець заблокований" (з RPC)

## Інтеграція майнінгу

### Вимоги до налаштування

**Конфігурація вузла**:
```bash
# bitcoin.conf
server=1
```

**Вимоги до гаманця**:
- Адреси P2WPKH для володіння плотом
- Приватні ключі для майнінгу (або адреса кування якщо використовуються призначення)
- Підтверджені UTXO для створення транзакцій

**Зовнішні інструменти**:
- `pocx_plotter`: Генерація файлів плотів
- `pocx_miner`: Сканування плотів та подання nonces

### Робочий процес

#### Соло-майнінг

1. **Генерація файлів плотів**:
   ```bash
   pocx_plotter --account <plot_address_hash160> --seed <32_bytes> --nonces <count>
   ```

2. **Запуск вузла** з сервером майнінгу:
   ```bash
   bitcoin-qt -server
   ```

3. **Налаштування майнера**:
   - Вкажіть на RPC-ендпоінт вузла
   - Вкажіть каталоги файлів плотів
   - Налаштуйте account ID (з адреси плоту)

4. **Запуск майнінгу**:
   ```bash
   pocx_miner --rpc-url http://localhost:8332 --plots /path/to/plots
   ```

5. **Моніторинг**:
   - Майнер викликає `get_mining_info` кожен блок
   - Сканує плоти на найкращий дедлайн
   - Викликає `submit_nonce` коли знайдено рішення
   - Вузол автоматично валідує та кує блок

#### Пул-майнінг

1. **Генерація файлів плотів** (так само як соло-майнінг)

2. **Створення призначення кування**:
   - Відкрийте діалог призначення кування
   - Виберіть адресу плоту
   - Введіть адресу кування пулу
   - Натисніть "Надіслати призначення"
   - Дочекайтеся затримки активації (30 блоків testnet)

3. **Налаштування майнера**:
   - Вкажіть на ендпоінт **пулу** (не локальний вузол)
   - Пул обробляє `submit_nonce` до ланцюга

4. **Робота пулу**:
   - Гаманець пулу має приватні ключі адреси кування
   - Пул валідує подання від майнерів
   - Пул викликає `submit_nonce` до блокчейну
   - Пул розподіляє винагороди за політикою пулу

### Винагороди Coinbase

**Без призначення**:
- Coinbase платить безпосередньо на адресу власника плоту
- Перевіряйте баланс на адресі плоту

**З призначенням**:
- Coinbase платить на адресу кування
- Пул отримує винагороди
- Майнер отримує частку від пулу

**Графік винагород**:
- Початково: 10 BTCX за блок
- Халвінг: Кожні 1050000 блоків (~4 роки)
- Графік: 10 → 5 → 2.5 → 1.25 → ...

## Усунення несправностей

### Типові проблеми

#### "Гаманець не має приватного ключа для адреси плоту"

**Причина**: Гаманець не володіє адресою
**Рішення**:
- Імпортуйте приватний ключ через `importprivkey` RPC
- Або використайте іншу адресу плоту, що належить гаманцю

#### "Призначення вже існує для цього плоту"

**Причина**: Плот вже призначено іншій адресі
**Рішення**:
1. Скасуйте існуюче призначення
2. Дочекайтеся затримки скасування (720 блоків testnet)
3. Створіть нове призначення

#### "Формат адреси не підтримується"

**Причина**: Адреса не є P2WPKH bech32
**Рішення**:
- Використовуйте адреси, що починаються з "pocx1q" (mainnet) або "tpocx1q" (testnet)
- За потреби згенеруйте нову адресу: `getnewaddress "" "bech32"`

#### "Комісія транзакції занадто низька"

**Причина**: Перевантаження мережевого mempool або занадто низька комісія для ретрансляції
**Рішення**:
- Збільшіть параметр ставки комісії
- Дочекайтеся очищення mempool

#### "Призначення ще не активне"

**Причина**: Затримка активації ще не минула
**Рішення**:
- Перевірте статус: скільки блоків залишилося до активації
- Дочекайтеся завершення періоду затримки

#### "Немає монет на адресі плоту"

**Причина**: Адреса плоту не має підтверджених UTXO
**Рішення**:
1. Надішліть кошти на адресу плоту
2. Дочекайтеся 1 підтвердження
3. Повторіть створення призначення

#### "Неможливо створювати транзакції з гаманцем тільки для перегляду"

**Причина**: Гаманець імпортував адресу без приватного ключа
**Рішення**: Імпортуйте повний приватний ключ, а не лише адресу

#### "Вкладка призначення кування не видима"

**Причина**: Вузол запущено без прапорця ``
**Рішення**: Перезапустіть з `bitcoin-qt -server`

### Кроки налагодження

1. **Перевірка статусу гаманця**:
   ```bash
   bitcoin-cli getwalletinfo
   ```

2. **Перевірка володіння адресою**:
   ```bash
   bitcoin-cli getaddressinfo pocx1qplot...
   # Перевірте: "iswatchonly": false, "ismine": true
   ```

3. **Перевірка статусу призначення**:
   ```bash
   bitcoin-cli get_assignment pocx1qplot...
   ```

4. **Перегляд недавніх транзакцій**:
   ```bash
   bitcoin-cli listtransactions "*" 10
   ```

5. **Перевірка синхронізації вузла**:
   ```bash
   bitcoin-cli getblockchaininfo
   # Перевірте: blocks == headers (повністю синхронізований)
   ```

## Найкращі практики безпеки

### Безпека адреси плоту

**Управління ключами**:
- Зберігайте приватні ключі адреси плоту безпечно
- Транзакції призначень доводять володіння через підпис
- Тільки власник плоту може створювати/скасовувати призначення

**Резервне копіювання**:
- Регулярно робіть резервні копії гаманця (`dumpwallet` або `backupwallet`)
- Зберігайте wallet.dat у безпечному місці
- Запишіть фрази відновлення якщо використовуєте HD гаманець

### Делегування адреси кування

**Модель безпеки**:
- Адреса кування отримує винагороди за блоки
- Адреса кування може підписувати блоки (майнінг)
- Адреса кування **НЕ може** модифікувати або скасовувати призначення
- Власник плоту зберігає повний контроль

**Випадки використання**:
- **Делегування на гарячий гаманець**: Ключ плоту в холодному сховищі, ключ кування в гарячому гаманці для майнінгу
- **Пул-майнінг**: Делегуйте пулу, зберігайте володіння плотом
- **Спільна інфраструктура**: Кілька майнерів, одна адреса кування

### Синхронізація мережевого часу

**Важливість**:
- Консенсус PoCX вимагає точного часу
- Дрейф годинника >10с викликає попередження
- Дрейф годинника >15с запобігає майнінгу

**Рішення**:
- Тримайте системний годинник синхронізованим з NTP
- Моніторте: `bitcoin-cli getnetworkinfo` для попереджень про зміщення часу
- Використовуйте надійні NTP-сервери

### Затримки призначень

**Затримка активації** (30 блоків testnet):
- Запобігає швидкому перепризначенню під час форків ланцюга
- Дозволяє мережі досягти консенсусу
- Не може бути обійдена

**Затримка скасування** (720 блоків testnet):
- Забезпечує стабільність для пулів майнінгу
- Запобігає атакам "griefing" через призначення
- Адреса кування залишається активною під час затримки

### Шифрування гаманця

**Увімкнення шифрування**:
```bash
bitcoin-cli encryptwallet "your_passphrase"
```

**Розблокування для транзакцій**:
```bash
bitcoin-cli walletpassphrase "your_passphrase" 300
```

**Найкращі практики**:
- Використовуйте надійну парольну фразу (20+ символів)
- Не зберігайте парольну фразу у відкритому тексті
- Блокуйте гаманець після створення призначень
